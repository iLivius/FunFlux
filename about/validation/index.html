    Validation on public genomes¶

    This page shows what FunFlux 2.0.0 produced on two public genomes, and how to repeat the runs. Read it to see, on real data, what each read-based mode delivers and how much the gene-finder settings change the annotation.

    Botrytis cinerea strain B05.10 was run from ONT and Illumina reads in the three read-based modes, illumina, longread and hybrid. Five comparison runs then annotated the genome of its hybrid run again in contigs mode. Cordyceps cateniannulata strain GXU-8616 was run from PacBio HiFi reads, alone and with MGISEQ short reads (PacBio HiFi reads). Flye has run in longread mode on both genomes but not in hybrid mode, where every run used hifiasm, the default assembler. The results are measurements on these two genomes, so read the limitations below before the numbers.

    Terms used on this page
    Tiberius a deep-learning gene finder with a fungi model its authors trained on many fungal genomes; on by default, it adds its gene models to funannotate's evidence
    annotation parameter table the tab-separated file named by files.annotation_params, one row per sample: name, species, a protein FASTA of related fungi and, optionally, an AUGUSTUS model
    protein evidence proteins aligned to the genome to support the gene models: the FASTA in column 3 of the annotation table, plus UniProt Swiss-Prot, always added
    stored AUGUSTUS model the AUGUSTUS parameters trained earlier for one species, kept in trained_species/ of the funannotate database; named in column 4, they are used as they are
    telomere array tandem copies of the telomere repeat unit at a contig end; by default 5 or more copies within 25,000 bp of the end make a telomere
    contig summary the table 02.assembly/{sample}/eval/contig_summary.tsv: one row per contig of the draft, with its evidence (telomeres, depth, rDNA units, genes) and a verdict such as chromosome or rDNA_array
    concatemer a contig of two or more copies of the mitochondrial genome joined end to end; flagged (concatemer_flag Y) unless the assembler reports it circular, never trimmed
    MGISEQ a short-read sequencer from MGI Tech (DNBSEQ technology) that produces paired reads like Illumina's; FunFlux ran such reads as Illumina pairs

    The numbers record what FunFlux does on a well-studied genome, not its accuracy on a new one

    • One genome for ONT and Illumina reads (n = 1). Nothing here shows how FunFlux does with ONT or Illumina reads of other fungi. The HiFi runs, on another genome, have their own limitations (below).
    • Tiberius has seen genes of this species. B. cinerea is one of the species the Tiberius fungi model was trained on (its training list). What Tiberius adds here may be more than it adds on a species it has not seen.
    • A stored AUGUSTUS model for B. cinerea, botrytis_cinerea, is in the funannotate database. Only one comparison run used it. Every other run trained AUGUSTUS on the genome's own BUSCO genes.
    • The protein evidence given to funannotate was the reference annotation's own 13,703 proteins, beside UniProt Swiss-Prot, which FunFlux always adds and which holds 194 reviewed B05.10 proteins. It pulls the gene models towards the reference. The agreement with the reference is therefore an upper bound, not what a new species gets with proteins of related fungi. Every run had the same evidence, so the runs stay comparable with each other.
    • The reference annotation is not a perfect answer key. NCBI lists it as submitted by Syngenta Biotechnology, Inc. and carried into RefSeq on 2018-04-17 by its annotation propagation pipeline. The RefSeq records are marked provisional (not yet given final NCBI review). The genome paper, whose authors include Syngenta staff, predicted the genes, used RNA-seq of more than 20 samples to check and improve them, and curated chromosome 1 by hand (van Kan et al. 2017). A FunFlux gene that differs from the reference is not necessarily wrong.
    • Run times come from one shared server, with other runs going on at the same time, so they are indicative only.

    What this page is¶

    The page is a record of what FunFlux 2.0.0 produced in these runs, with their settings. It checks that each mode gives a sensible genome and gene set, and it measures how much two annotations of the same genome, with the same gene-finder settings, differ. It is not a benchmark, because it has one genome per read type and one replicate. Nor is it a comparison with other tools or pipelines, or a measure of accuracy on a species the gene finders have not seen.

    B05.10 was chosen because it has a gapless genome, a gene set and public reads of the strain itself. The assembly, the genes, the mitochondrion and the β-tubulin change can therefore be set against published records:

    • A gapless reference genome, which its authors call near-finished: 18 chromosomes in 18 sequences without gaps, 42.6 Mb.
    • A reference annotation of 11,698 protein-coding genes.
    • Public reads of the strain: ONT reads from the reference's own sample record, and Illumina pairs of a lab stock.
    • Features to check: telomeres at both ends of 10 of the 18 reference chromosomes (van Kan et al. 2017), and the β-tubulin change E198A, which the reference protein carries too (AMR worked example).

    One of these changes shapes every gene result of the B05.10 runs: column 3 of the annotation table gave the reference's own proteins as evidence (see the limitations above).     Assembly per mode¶

    The first table sets the genome of each mode run against the 18 chromosomes of the reference. Every run with long reads used hifiasm, the default assembler, except the one marked Flye, which ran Flye 2.9.6 with --nano-hq, as flye_input_mode: auto chose.

    On B05.10, the three hifiasm runs with long reads put each of the 18 chromosomes into one contig and cover almost all of each. Flye, on the same 136x reads, is as contiguous (N50 2.58 Mb), but puts 16 chromosomes into one contig and ends fewer contigs in a telomere array. The Illumina-only run gives 409 contigs, no chromosome in one piece, and leaves up to 4 % of a chromosome uncovered.

    • Contigs and length are those of contigs_final.fasta, the nuclear genome, from QUAST. The hifiasm 136x and hybrid assemblies are 1.4 Mb longer than the reference. Most of the extra length is in 13 contigs that the contig summary calls rDNA_array (0.98 Mb in the hifiasm 136x run, 0.78 Mb in the hybrid run), which are pieces of the rDNA array. The 42x and Flye runs have no such contigs.
    • The Flye run has chromosomes 1 and 13 in two pieces each (2.72 and 1.39 Mb; 1.95 and 0.31 Mb). Its genome is 0.32 Mb longer than the reference.
    • Telomeres come from FunFlux's contig summary: arrays of the repeat unit it chose, AACCCT, at both contig ends. AACCCT is tidk's canonical form of TTAGGG, the same repeat read on the other strand. The hifiasm long-read runs have 14 or 15 such contigs, and in each, 3 or 4 more chromosomes lack an array at one end. In the Flye run, 23 contig ends carry an array, against 32 to 34 in the hifiasm long-read runs. The reference's 10 comes from its paper, not from FunFlux's search, so it is not the same measure.
    • Filtlong guidance was on in the hybrid run. The unguided longread 136x run, on the same ONT reads, has 32 contigs against 33, and all 18 chromosomes in one contig in both. That is one reason the guidance is off by default (Filtlong guidance).

    Every assembly differs from the reference by 15 to 39 substitutions and 12 to 36 small indels per Mb. In the long-read assemblies most substitutions sit in a few regions, and in every run most small indels sit in runs of identical bases. Each run took 8 to 12 hours.

    • Substitutions are not spread out. In each long-read assembly more than 90 % of them fall in ten windows of 10 kb of the reference. They mark a few regions where the assembly and the reference disagree, not errors along the whole genome.
    • Small indels, of 1 to 10 bp, are spread out. In every run three quarters or more of them (77 to 86 %) sit in a run of at least 3 identical bases of the reference. The hybrid assembly, corrected with the Illumina reads by Polypolish, has about a third fewer than the hifiasm 136x assembly without Medaka. The 42x run with Medaka also differs from the hifiasm 136x run in depth, so it does not measure Medaka alone, while Medaka on the 42x run does. The Illumina contigs differ least, but they cover less of each chromosome.
    • Not an error rate. Some of these differences may be errors of the reference itself or real differences between lab stocks. The counts compare the runs with each other.
    • Run time is that of the main Snakemake run, from its log. In the four runs without Flye, the ITS classification, the contig summary and the AMR screen were run afterwards on the finished output. They took under a minute each, so the times above leave out at most a few minutes.

    To count the chromosomes and the differences, each contigs_final.fasta was aligned to the reference with minimap2 2.31 (-x asm5 -c --cs). A contig is placed on the chromosome that most of its bases align to, and a chromosome counts as one contig when the largest contig placed on it is at least 97 % of its length. The share of each chromosome covered counts alignments with a mapping quality of at least 5. Differences are counted in the alignments with a mapping quality of at least 30, per Mb of aligned contig.

    Medaka on the 42x run¶

    The 42x run keeps both the assembly that Medaka polished (contaminants/contigs_decontam.fasta) and Medaka's result (medaka/consensus.fasta). Medaka can therefore be measured alone, on the same reads and the same assembly, before and after. QUAST 5.3.0 compared both with the reference, and BUSCO 6.0.0 scored both, and the reference, with ascomycota_odb12.

    Before Medaka After Medaka Reference

    Contigs, misassemblies, genome fraction 19, 30, 99.98 % the same –

    Medaka removed 289 indels, 15 %, most of them 5 bp or shorter, and added 14 mismatches. The number of contigs and of misassemblies, the genome fraction and the BUSCO completeness did not change. The BUSCO genes with internal stop codons went from 483 to 479, but Medaka's gain is too small to show in the genes. The reference itself has as many such genes (482), so that count measures BUSCO's alignments, not the assembly. Medaka took 15 minutes on 12 threads.

    • The model, r1041_e82_400bps_sup_v5.2.0, is a guess, because the public reads carry no basecaller tag in their headers. The reads look like R10.4.1 reads called with a "sup" model (median identity to the reference 98.97 %, median read quality Q20.5, on 20,000 reads), so the guess is plausible.
    • These counts are QUAST's, over all aligned bases. The table of differences under Assembly per mode counts differently (minimap2, mapping quality of at least 30, indels of 1 to 10 bp), so the two tables cannot be compared number for number.

    Gene models per mode¶

    The gene models of each mode run were set against the reference annotation, to see how much the assembly changes the genes.

    Run Protein-coding genes BUSCO complete (of 1,312) Reference genes found FunFlux genes that match Matching genes
    Reference (RefSeq) 11,698 – – – –
    longread, ONT 136x 11,802 1,301 (99.2 %) 90.4 % 89.7 % 10,591
    longread, ONT 136x, Flye 11,760 1,302 (99.2 %) 90.2 % 89.8 % 10,560
    longread, ONT 42x + Medaka 11,778 1,301 (99.2 %) 90.1 % 89.6 % 10,554
    illumina, Illumina 79x 11,704 1,302 (99.2 %) 90.4 % 90.5 % 10,590
    hybrid, ONT 136x + Illumina 79x 11,830 1,301 (99.2 %) 90.7 % 89.8 % 10,623

    On B05.10, the assembly mode and the assembler made little difference to the genes

    The runs predict 11,704 to 11,830 protein-coding genes, and 10,554 to 10,623 of them match a reference gene: a spread of 69, under 1 % of the genes.

    • BUSCO complete is the number of BUSCO dikarya_odb9 genes found complete among the predicted proteins, as funannotate annotate reports it. The five runs differ by at most one BUSCO gene.
    • Reference genes found is the share of the reference's gene loci with a matching FunFlux gene (gffcompare's locus sensitivity). FunFlux genes that match is the share of FunFlux genes with a matching reference gene (locus precision). Both are about 90 % in every run.
    • A match means that the coding part of the FunFlux gene has the same introns as a reference transcript, while its start and stop may differ. A gene without introns matches when the two overlap almost completely.
    • tRNA genes, 211 in every run, are left out of all counts.

    To compare the genes, Liftoff 1.6.3 carried the reference genes onto the genome FunFlux annotated: all 11,698 of them, but 11,697 onto the Illumina assembly. Then gffcompare 0.12.10 compared the coding parts of the two gene sets (Shumate & Salzberg 2021; Pertea & Pertea 2020). These tools were used for this page only and are not part of FunFlux.

    Repeated runs and the gene finders¶

    To tell run-to-run noise from the effect of each gene finder, one genome was annotated six times: the hybrid run, and five contigs-mode runs on its contigs_final.fasta. The five ran at the same time, each with 20 CPU threads instead of the hybrid run's 32. All six annotated the same masked genome, byte for byte. The default run used Tiberius, GeneMark-ES and AUGUSTUS trained on the genome.

    Run What changed, besides the mode and the threads Protein-coding genes Genes identical to the default run Matching genes Matching genes, difference from the default
    Default (the hybrid run) – 11,830 – 10,623 –
    Replicate nothing 11,825 11,718 10,619 −4
    No GeneMark-ES genemark.mode: off 11,834 11,253 10,590 −33
    No Tiberius tiberius.mode: off 11,729 10,494 10,257 −366
    Neither both off; AUGUSTUS, SNAP and GlimmerHMM remain 11,503 9,528 9,630 −993
    Stored AUGUSTUS model annotation table, column 4: botrytis_cinerea 11,934 11,277 10,694 +71

    In these runs, two annotations of the same genome with the same gene-finder settings differ at about 1 % of the genes, but by only 4 matching genes. Differences of a few hundred genes are therefore unlikely to be noise. Tiberius matters most: without it about 3 % of the matching genes are lost, and about 9 % without both Tiberius and GeneMark-ES. GeneMark-ES on its own makes a small difference (33 genes), which one replicate cannot separate from noise. The stored B. cinerea AUGUSTUS model adds 71. Read these numbers with the head start described in the note below.

    • The replicate. 112 of the 11,830 genes of the default run differ in the replicate. The matches lost (38) and gained (34) almost cancel, hence the difference of 4.
    • Noise. One replicate is one measurement of the run-to-run noise, not its range, and it holds any effect of the thread count as well.
    • The stored AUGUSTUS model is AUGUSTUS's model for B. cinerea itself.
    • Identical means the same coding intervals: every exon, the start and the stop. Run-to-run differences explains which steps differ between runs with the same input and settings, and why.
    • Run time. Each comparison run took 7.6 to 9.5 h.

    Tiberius and the stored AUGUSTUS model had a head start on this species

    Tiberius was trained on B. cinerea among many other fungi, and the stored AUGUSTUS model is a B. cinerea model. Both may therefore add more here than on a species they have not seen. Every run also had the reference's own proteins as evidence, which brings all runs closer to the reference and may hide part of what the gene finders add. These runs are consistent with Tiberius being on by default and GeneMark-ES being optional (Gene prediction), but they do not measure what Tiberius adds on a new species.

    Other results¶

    The ITS taxonomy and the AMR screen gave the same result in all five mode runs, so in these runs they depend neither on the mode nor on the assembler:

    • ITS taxonomy. The main ITS2 sequence gives the genus Botrytis (confidence 0.99) and the species B. caroliniana (0.83), not the strain's species. The main ITS1 sequence stops at the family Sclerotiniaceae (0.93). See ITS taxonomy.
    • AMR screen. It finds β-tubulin E198A, with the verdict resistance (carbendazim, iprodione). Bos1 and OS1 are wild type, and cytochrome b is not evaluated. See the worked example of the AMR page.

Each run therefore counts its mitochondrial contigs (one, or four in illumina) on top of the nuclear contigs of the assembly table. The contig summary also lists the 42x and hybrid mitochondria at their draft lengths, 116,228 and 174,832 bp.

    PacBio HiFi reads: Cordyceps cateniannulata GXU-8616¶

    Three runs used PacBio HiFi reads of one strain of an insect-pathogenic fungus (family Cordycipitaceae). Two ran in longread mode, one with hifiasm, the default assembler, and one with Flye. The third ran in hybrid mode, which adds MGISEQ short reads of the same strain. On this genome the runs show that the HiFi path works from reads to annotation, and how close its genome comes to a chromosome-scale reference.

    The HiFi runs do not measure the accuracy of the genes

    • One genome (n = 1). Nothing here shows how FunFlux does on HiFi reads of other fungi.
    • The reference comes from the same sample. It was assembled from HiFi reads with hifiasm 0.19.8, polished with short reads and joined into 7 chromosomes with Hi-C data (Liu et al. 2026). The sample's only HiFi run in the archive is the one used here. The reference is chromosome-scale with the help of Hi-C, while reads alone may not give every chromosome in one piece. Agreement with it, above all for the hifiasm runs, is expected and is not an independent check.
    • No gene comparison. The reference's gene annotation (10,743 protein-coding genes at NCBI) was not compared with FunFlux's genes. The gene table gives counts and BUSCO only.
    • Tiberius has seen no genes of this genus, only genes of the same family. No Cordyceps species is among the training species of the Tiberius fungi model, but two species of the same family, Akanthomyces muscarius and Beauveria bassiana, are (its training list).
    • The protein evidence comes from another species, Cordyceps militaris CM01, as for a new genome. The B05.10 runs had the reference's own proteins, which pull the genes towards the reference.
    • Run times come from one shared server, with other runs going on at the same time, so they are indicative only.

    On this genome, both assemblers give six of the seven reference chromosomes as one contig each, with a telomere array at both ends, and cover all of every reference chromosome. The seventh breaks in two at its rDNA array. Both assemblies also hold about 1.3 Mb that the reference lacks.

    • Chromosome 7 (3.58 Mb) comes as a piece of 3.10 Mb and one of 0.52 Mb, or 3.07 and 0.51 Mb with Flye. Each piece ends in a telomere array. The break lies in the tandem copies of the rDNA unit, the repeat that holds the ITS.
    • The extra 1.3 Mb. hifiasm gives it as one contig of 1,329,053 bp with a telomere array at both ends, the seventh chromosome in the next table. Flye gives it as four contigs, 1.30 Mb together. Only 4 % of it aligns to the reference, in short pieces. Its read depth is close to that of the chromosomes (1.14 times the median), and FunFlux predicts 275 genes on it. The contamination and mitochondrion screen places it in Cordyceps from its BLAST hits. Whether it is a small chromosome that the reference lacks was not checked further.
    • Other contigs. hifiasm adds 7 small contigs of rDNA units (rDNA_array, 0.34 Mb together) and 2 contigs with almost no read depth (low_depth, 0.17 Mb) that do not align to the reference. Flye has neither, and its genome is 0.57 Mb smaller.
    • hybrid. Its draft assembly is the hifiasm run's, byte for byte, because both runs filter and assemble the same HiFi reads. Polypolish then changed 38 positions with the short reads.
    • Run time is that of the main Snakemake run, from its log. The Flye run stopped once in InterProScan, with an error that did not come back when the run was started again by hand. Its time is the sum of both attempts, 3.7 and 3.6 h. The run was made without the second attempt that FunFlux makes by itself after a failed InterProScan job (Running FunFlux).

    The assemblies were checked as for B05.10, with minimap2 2.31 (-x asm5), and a chromosome counts as one contig when the largest contig placed on it is at least 97 % of its length. The reference's telomeres were counted with FunFlux's own telomere search, run on the reference, which found AACCCT arrays at both ends of all 7 chromosomes.

    With hifiasm, all 14 ends of the reference chromosomes and both ends of the extra contig carry a telomere array. With Flye, the 14 reference ends do too, but the extra 1.3 Mb has an array at one end only and comes as three nuclear_contigs and one chromosome_arm. Flye's 0.51-Mb piece of chromosome 7 is unclassified, because its read depth, 1.74 times the median, is above the 1.5 limit.

    A circular mitochondrial contig of two copies is not flagged as a concatemer

    The mitochondrion published for this strain is 24,712 bp (Liu et al. 2026). Flye gives one copy. hifiasm marks its 49,194-bp contig as circular, so the concatemer flag stays N although the contig holds about two copies. FunFlux sets the flag to Y only when length_ratio is above 1.5 and the assembler did not record the contig as circular. length_ratio is the contig length divided by the length of the mitochondrial genome it best matches in BLAST (Concatemers).

    AMR screen and ITS¶

    The AMR screen and the ITS classification gave the same result in all three runs.

    A species outside the AMR database is reported, not failed, and the run goes on

    Cordyceps cateniannulata is not among the 57 species of the ChroQueTas database, so the three runs report it as not screened. amr_summary.tsv has one row with status not screened, and a NOTE in the log gives the reason. The database holds no Cordyceps, and its only species of the same family is Beauveria bassiana (The species).

    The ITS taxonomy is the same in all three runs. The main ITS2 sequence (158 bp) gives the strain's own species, C. cateniannulata (confidence 0.96, and 0.97 for the genus Cordyceps). The main ITS1 sequence (182 bp) stops at the phylum Ascomycota (class 0.60, below the cutoff of 0.8). The main ITS sequences themselves are the same in all three runs. The hifiasm assemblies hold 43 copies of the main ITS1 and 44 of the main ITS2, the Flye assembly 4 of each. See ITS taxonomy.

    To repeat the HiFi runs¶

    The HiFi runs can be repeated from public data. First download the reads, the protein evidence and the reference genome:

    # the reads (ENA); ENA names the HiFi file _subreads, but it holds HiFi reads
wget ftp://ftp.sra.ebi.ac.uk/vol1/fastq/SRR342/059/SRR34289959/SRR34289959_subreads.fastq.gz \
     ftp://ftp.sra.ebi.ac.uk/vol1/fastq/SRR342/058/SRR34289958/SRR34289958_1.fastq.gz \
     ftp://ftp.sra.ebi.ac.uk/vol1/fastq/SRR342/058/SRR34289958/SRR34289958_2.fastq.gz

# the protein evidence and the reference genome (NCBI Datasets)
curl -L -o GCF_000225605.1.zip \
  "https://api.ncbi.nlm.nih.gov/datasets/v2/genome/accession/GCF_000225605.1/download?include_annotation_type=PROT_FASTA"
curl -L -o GCA_056505955.1.zip \
  "https://api.ncbi.nlm.nih.gov/datasets/v2/genome/accession/GCA_056505955.1/download?include_annotation_type=GENOME_FASTA"
# unpack both into ncbi_dataset/data/<accession>/ (protein.faa; the genome FASTA);
# -o because both zip files hold files of the same name, such as README.md
unzip -o GCF_000225605.1.zip
unzip -o GCA_056505955.1.zip

    Name the reads GXU8616_pacbio.fastq.gz, GXU8616_R1.fastq.gz and GXU8616_R2.fastq.gz. The sample name, GXU8616, is the strain name without the hyphen. The longread runs had a folder with the _pacbio file only. Write the annotation table with the C. militaris proteins in column 3:

    #sample species proteins    augustus_species
GXU8616 Cordyceps cateniannulata    /path/to/ncbi_dataset/data/GCF_000225605.1/protein.faa  -

    Then use the settings above, and run as in How to reproduce, step 5.

    How to reproduce¶

    The B05.10 runs can be repeated from public data in five steps.

    1. Download the data:

      # the reference: genome, annotation and proteins (NCBI Datasets)
curl -L -o GCF_000143535.2.zip \
  "https://api.ncbi.nlm.nih.gov/datasets/v2/genome/accession/GCF_000143535.2/download?include_annotation_type=GENOME_FASTA&include_annotation_type=GENOME_GFF&include_annotation_type=PROT_FASTA"
unzip GCF_000143535.2.zip   # ncbi_dataset/data/GCF_000143535.2/: the genome FASTA, genomic.gff, protein.faa

# the ONT reads (sra-tools)
fasterq-dump SRR40741277 && gzip SRR40741277.fastq

# the Illumina pairs (ENA)
wget ftp://ftp.sra.ebi.ac.uk/vol1/fastq/SRR106/011/SRR10692911/SRR10692911_1.fastq.gz \
     ftp://ftp.sra.ebi.ac.uk/vol1/fastq/SRR106/011/SRR10692911/SRR10692911_2.fastq.gz

    2. Name the reads B0510_ont.fastq.gz, B0510_R1.fastq.gz and B0510_R2.fastq.gz, as the modes expect (Choosing a mode). Symbolic links are fine. For the 42x run, take the first 95,000 ONT reads, 4 lines each, as sample B0510m:

      zcat SRR40741277.fastq.gz | head -n 380000 | gzip > B0510m_ont.fastq.gz

    3. Write the annotation table, tab-separated, with the reference proteins in column 3. Add a line for B0510m for the 42x run, and write botrytis_cinerea in column 4 for the run with the stored AUGUSTUS model:

      #sample species proteins    augustus_species
B0510   Botrytis cinerea    /path/to/ncbi_dataset/data/GCF_000143535.2/protein.faa  -

    4. Copy the configuration template and set the mode, the input folder, the databases and the settings in the settings table. For the comparison runs, use contigs mode with the hybrid run's 02.assembly/B0510/contigs_final.fasta, named B0510.fasta.

    5. Run each configuration, with --cores equal to its resources.threads (Running FunFlux):

      snakemake --sdm conda --cores 32 --configfile config/config_custom.yaml

    To compare a B05.10 run with the reference, Liftoff carries the reference genes onto the genome FunFlux annotated, 04.annotation/{sample}/contigs_sort.fasta. Then gffcompare compares the coding parts of the lifted reference genes with FunFlux's protein-coding genes. The commands are in the box below.

    The comparison commands are not part of FunFlux 
    REF=ncbi_dataset/data/GCF_000143535.2
# 1. carry the reference genes onto the annotated genome (its contigs are named scaffold_N)
liftoff -g $REF/genomic.gff -o lifted_reference.gff3 -u unmapped_reference_genes.txt -p 16 \
  -dir liftoff_tmp -polish 04.annotation/B0510/contigs_sort.fasta \
  $REF/GCF_000143535.2_ASM14353v4_genomic.fna
# 2. rebuild the lifted reference transcripts from their coding parts only (CDS lines become
#    exons), because FunFlux's genes have no untranslated regions
awk -F'\t' 'BEGIN{OFS="\t"} /^#/ {print; next} $3=="exon" {next} $3=="CDS" {$3="exon"; print; next} {print}' \
  lifted_reference.gff3_polished | gffread -T -o lifted_reference_cds.gtf -
# 3. FunFlux's protein-coding genes (-C leaves out the tRNA genes, which have no CDS)
gffread -T -C -o funflux_coding.gtf \
  04.annotation/B0510/funannotate/annotate_results/Botrytis_cinerea_B0510.gff3
# 4. compare: gffcmp_cds.stats holds the sensitivity, the precision and the matching counts
gffcompare -r lifted_reference_cds.gtf -o gffcmp_cds funflux_coding.gtf

# the chromosome check: align the nuclear genome to the reference
minimap2 -x asm5 -c --cs -t 8 $REF/GCF_000143535.2_ASM14353v4_genomic.fna \
  02.assembly/B0510/contigs_final.fasta > contigs_vs_reference.paf

    All of these tools come from bioconda: Liftoff 1.6.3 (its own alignments made with minimap2 2.24), gffread 0.12.9, gffcompare 0.12.10, and minimap2 2.31 for the chromosome check.
